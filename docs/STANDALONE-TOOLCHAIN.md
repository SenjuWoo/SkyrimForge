# Standalone setup and owner updates

Forge runs independently of the general AI bundle. Run `START-HERE.bat` to install its runtime, Skyrim skill pack and provider bridge. It uses Python 3.11+ and its own healthy app venv; Python's base interpreter is shared. Forge ships its native helper, so Go, CMake, Visual Studio and the Windows SDK are **not** prerequisites for ordinary CLI/MCP jobs.

## Python ownership

Setup checks `UABS_PYTHON` in the current process, then the user environment, then a healthy existing Forge environment and installed interpreters. A compatible manual base is preserved. `-BootstrapPython` permits the official install manager to update an already managed base with `pymanager install --update --yes <existing-tag>` on the same major/minor and architecture. It does not migrate feature lines or rebuild a healthy app venv. An unowned/manual base produces an explicit update-unverified diagnostic.

Only when no compatible runtime exists does setup provision the [official Python install manager](https://docs.python.org/3/using/windows.html) through its documented Store/WinGet identity (`winget install 9NQ7512CXL7T -e`), then `pymanager install --yes default`. The manager verifies official packages. Forge records the resolved shared executable in `UABS_PYTHON`; it does not download its former pinned Python installer. Without WinGet, the error links directly to Python's installer. Calling `Install-or-Update.ps1` without `-BootstrapPython` performs no runtime update/download; CI and offline installation use that boundary.

## Updating Forge

`Update Forge.bat` / `Update-Forge.ps1` queries this repository's latest **stable** release. It requires the expected versioned archive and GitHub SHA-256 asset digest, verifies every payload manifest entry, rejects traversal/links, stages only manifest-owned release files and keeps the prior owner payload beside it as `.forge-backup-<id>`. Private files, app venvs and workspace trees move intact into the replacement, without copying or traversing their contents; workspace junctions remain junctions. Private files inside owner directories also survive. A private path colliding with a newly owned path stops the update before replacement. Removed owner files remain only in the backup. Git development checkouts and newer versions are kept. Existing owner files must match their previous manifest hashes before replacement; an edited file stops the update intact. `VERSION.txt` is the separately parsed version marker. An equal version succeeds only when the installed owner payload matches; a mismatch requires inspection or a newer verified release. A stable sibling `.<owner-folder>.forge-update.lock` serializes updates through setup and rollback; its empty file remains after completion to prevent lock races. Close a running client if Windows reports an in-use file; never point the updater at a game directory.

`Update-Forge.ps1 -CheckOnly` reports availability without downloading/replacing the payload. For offline controlled installation, pass `-Archive`, `-Sha256`, and `-ReleaseVersion`; these values identify an already obtained owner release. `-SkipSetup` supports isolated fixture/payload checks and does not claim provider reconnection. A failed swap, setup exception or nonzero setup exit returns moved private entries before restoring the old root. The backup retains the previous release files; private content lives at the active root. To restore that release manually, close its clients, retain the active root, restore the backup at the same path and move the active private entries into it without replacing release files. Runtime/provider setup retains its own preservation and rollback rules. Failed operations are recorded in `%LOCALAPPDATA%/Skyrim-Forge/logs/owner-update.log`; successful updates name the recoverable backup there as well.

A verified local source payload uses `Update-Forge.ps1 -Root <installed-root> -SourceDir <source-root> -SkipSetup`. Source and destination must be separate. This mode checks the selected version, manifest identity, every file hash and staged bytes; it copies only manifest files and generated release reports, excluding source-only `.git`, `.venv` and other private content. The installed version marker still prevents downgrades. `-SkipSetup` lets the calling installer run Forge setup once after the payload swap.

The owner updater updates Forge. houseCARL's existing owner installer advances older supported copies with backups and preserves newer versions/settings. Other tools remain controlled by their own repositories or installation managers; discovery never silently downloads a GUI or executes an unverified CLI.

## Reusing Reverse THIS!

Setup consumes `%LOCALAPPDATA%/ReverseThis/kit.json` when present. `forge tool-reuse-reverse --approve` also performs this explicitly. The owner manifest's DirectXTex and 7-Zip directories supply the exact `texconv.exe` and `7z.exe` paths. Forge verifies available per-file owner hashes, validates the 7-Zip sidecar, pins current bytes, and configures the existing broker: no second vault copy is made. Config is backed up before changes. A small `.reverse-bindings.json` receipt beside the config lets later runs refresh only previously automatic bindings after an owner update. Custom paths or changed pins stay untouched.

## SDK vault

`forge sdk-status` lists the pinned SDK sources (CommonLibSSE-NG, vcpkg and reference lineages) and the host build tools it can see (git, cmake, ninja, xmake, vcpkg, MSVC C++ tools). `forge sdk-install --approve` fetches the default set by commit SHA into `sdk-vault` beside the tool vault; add ids or `--all` for the reference lineages and `--bootstrap` to build `vcpkg.exe`, then pin it with `forge tool-configure vcpkg <vcpkg.exe> --approve`. See [native source lock](NATIVE-SOURCE-LOCK.md).

## Build-only prerequisites

Rebuilding Forge's shipped helpers needs the Go version pinned in CI. Building a user SKSE/CommonLib project needs the configured CMake, vcpkg and Visual Studio C++/SDK toolchain; its project manifests keep exact dependency pins. The optional general bundle can provision shared build tools, but Forge's normal install does not fetch unused SDKs. See [native engineering](NATIVE-PLUGIN-ENGINEERING.md) and [local tool coverage](LOCAL-TOOL-COVERAGE.md).
